# Pilot — domain glossary

Use these words in code, cards and docs. Avoid the alternatives in brackets.

- **Hyper** — the layer modifier: while the layer key is held, every key is a Pilot bind. Presented to users as "Hyper". (not "hyperkey", "meh", "super")
- **Layer key** — a physical key that is Hyper: Caps Lock (default, remapped to F18 at the HID level), left or right Control, left or right Option, or left or right Command. A modifier picked is Hyper alone and no longer itself; its other side still is, so only one side of a modifier can be on (left Command picked, Cmd+C needs right Command). Picked in onboarding; General can turn on more than one, each Hyper alone. (not "trigger key")
- **Chord Hyper** — a real cmd+ctrl+alt chord sent by a keyboard (the Keychron knob macros); counts as Hyper for keys Pilot binds and passes through untouched otherwise.
- **Bind** — one trigger mapped to one action, e.g. Hyper+Shift+B → open browser. Users make binds; they never write config. (not "shortcut", "hotkey" — those words are for macOS's own and other apps')
- **Trigger** — what the user presses: Hyper plus a sublayer and a key, or a plain combo.
- **Sublayer** — the extra modifiers held with Hyper: none, Shift, Ctrl, Alt, Shift+Ctrl. Each is a section of the Binds screen and a page of the overlay. (not "tier" — that word is taken, below)
- **Mouse trigger** — a mouse button, a media key or key a mouse sends, or the wheel, bound on Binds › Mouse and kept in binds.json's `mouse` rows (schema 3). Each button has its plain press and, with Hyper held, a second one (Hyper + Back); the wheel's rolling binds only with Hyper held: Hyper + scroll up, Hyper + scroll down (P51). Button 3, the wheel's press, is the Wheel click (not "Middle", P57) and binds plain and under Hyper like any button. `pilot list mouse` names each by its label, "Mouse 4" or "Hyper+Mouse Scroll Up" (P58). (not "mouse bind" for the trigger itself; the bind is the trigger and its action)
- **Plain combo** — a trigger without Hyper, e.g. left Alt+H or cmd+ctrl+X: at least one of cmd, ctrl, alt, left and right told apart, own section in the Binds screen, warned about when it shadows a macOS shortcut or accent typing.
- **Hold** — a mouse trigger held past Hold after (180 ms, Launcher › Rings), a trigger of its own: "Mouse 4 Hold", in binds.json's optional `holds` list (P74). Its press waits; held longer its bind runs (a ring), let go sooner it is the button's click: its own bind, or with none a media key goes on to macOS's Now Playing, and a button's or a keystroke's does nothing (Sven, Q370). Never under Hyper. (not "long press")
- **Ring** — the Ring menu (P74, after Opie; design Halo): up to eight wedges around the pointer, opened by holding a key or a button's hold bound to `rings.open:<ring>`; flick toward a wedge and let go, or click it. A group nests as the menu's branches do: entering it turns the ring into the group's own ring in the same place, a rest in the hub or Esc going back up a level (crossing the hub never does); past eight, More pages. The Pilot ring is the Hyper+Space menu's root as Sven arranged it, its extra rows too, each branch filled as it opens. Edited, and given a key or a button's hold, in Launcher › Rings. Rings live in rings.json (schema 2); a ring for one app opens first while it is in front; scroll at the top steps to the next ring. (not "pie menu", "radial", "wheel" — the wheel is the mouse's)
- **Wedge** — one of a ring's eight places, north first, clockwise: an action, a switch (an action showing ON or OFF, read as the ring opens) or a group, written by hand or filled from a menu branch, entered as its own ring, groups inside groups. (not "slot", "segment")
- **Action** — one thing Pilot can do: snap left, go to workspace 3, open terminal, lock. Every action is bindable; each has an id, a label, a default key and a tier. (not "command")
- **Ability** — anything Pilot can do as Launcher › Abilities lists it (story 155): every action, plus what the Hyper+Space menu answers when typed (the calculator, file search, Ask AI), which no action names. (not "feature")
- **Module** — a group of actions with one mechanism: Engine, Windows, Workspaces, Apps, Drive, Captures, System, Media, Dictation, Rings (`Module` in PilotCore's ActionRegistry); later the Game.
- **App shortcut** — an app's own menu item with the key set over it on Binds › Per app › App shortcuts (story 151): an app bind that presses the item, or one that turns the app's own shortcut off. (not "app bind" in general: an app bind can run any action) Parked 2026-10-10 with per-app binds (branch parked/per-app-binds); binds.json keeps them, unused.
- **Preset** — a named bind set, picked on the Binds screen or at onboarding's Keys step: a base table (Easy, Complex, Scratch, Classic, My binds, or empty for a New preset from scratch) plus the keys set in it, which stay with it. Easy, Complex and Scratch are built in for everyone; Classic is listed only for a binds.json that already holds it (an install from 1.3 or earlier), My binds likewise (SH8), so a new user sees the three; the rest are made by hand or imported, and can be renamed and deleted. An imported preset on a table this Mac does not list lands on the empty base with its keys set by hand (T14). App binds (parked 2026-10-10, kept in binds.json) stay across every preset; Reset all goes back to the active preset's base. (not "pack" — a pack is exported binds; not "key preset" in code, where `BindStore.Preset` is the name)
- **Default bind set** — Easy, the preset a new install starts on (pilot-ui-redesign T11, Sven 2026-11-19, Q264). From 1.0 to 1.3 it was Pilot default, now Classic; before 2026-10-09 it meant the Omarchy preset: Omarchy's layout on Hyper, taken from the Mac column of Sven's shared keymap (`~/code/dotfiles/keymap/keymap.toml`). Resettable from the Binds screen. (not "Pilot default", the 1.3 name; not "starter pack" — the pack picker is v2)
- **Easy** — the key preset a new install starts on (Q264): letters you can guess (B browser, Return terminal, V clipboard, S capture area, Space the menu) and focus on the arrows, every key in Complex too, none for an app a Mac may lack; frozen in `PilotDefault.easy` (pilot-key-presets.html, approved 2026-11-19).
- **Complex** — the key preset with Easy's keys plus every window move: swap on Shift+arrows, nudge on Control+arrows, workspaces 1 to 9 and sending a window there, the ¾ and ¼ splits; no app a stranger may not have (no GitHub, YouTube or X, Q2 2026-11-19). `PilotDefault.complex`.
- **Scratch** (key preset) — the key preset with no keys at all (Open question 12): you build your own; Pilot's menu bar icon still opens Pilot. (not the quick note of the same name, below; not "Start from scratch", the 1.3 base that kept Hyper+Space)
- **Classic** (key preset) — Pilot default from 1.0 to 1.3, Sven's Arrows 2 layout frozen on 2026-10-28 (Q531), kept unchanged under preset id `pilot` so an upgraded install keeps every key it learned (Q3, 2026-11-19); listed only for a binds.json that holds it, never offered at onboarding. `PilotDefault.binds`. (not the menu's Classic layout: no longer a layout of its own since the feature trim, its look kept as Line's root list)
- **Keys step** — onboarding's third step, between Access and Set up (T12, T13): "Which keys should Pilot start with?", Easy, Complex and Scratch as three cards side by side at 780 (Q4), each with a few keys and "and N more", picked with 1, 2 or 3; an install on Classic or a preset of its own picks none and Keep my keys keeps it. Saved resume point `keys`.
- **Interim layout** — Sven's own keys as they were on 2026-10-04: the My binds preset, selectable on a Mac whose binds.json already holds it, never offered to a new user.
- **Default apps** — what the Open with page sets (story 163): the main editor and the app macOS opens each kind of file and link with, changed only on a pick. (not "file associations", not "Defaults", the page's name until C3)
- **Main editor** — the Editor role's app: Sven's pick on Open with, else the Mac's default for text when it is an editor, else VS Code, Cursor, Zed or Sublime Text, else TextEdit. Its key opens it and Configs open files in it. (not "default editor", which is macOS's per file kind)
- **Configs** — the app window page, and the menu's Config branch (a More rows extra, off by default), listing the config files of the apps on this Mac, read-only, each opened in the main editor; its Agents tab lists the agents' settings (Claude Code, Codex, Hermes, Empryo, opencode; on Configs itself until 2026-10-19) and the files agents read before they work (the Agent instructions page until the page map, Sven 2026-10-17). (not "dotfiles", which is Sven's repo the files often live in)
- **Menu** — the searchable, hierarchical panel Hyper+Space opens, set up on the Launcher page. Branches: Apps, Learn, Actions (id `trigger`), Install, Remove, Update, Clean, Extensions, About (this Mac and Pilot, Omarchy's About, Q443), System; the root shows only these, in Sven's order minus the ones he hid (Launcher › Your menu, story 152), with any extra rows he switched on (More rows: Config, which left the default root on Sven 2026-10-21, Files, Notes, QR, Stats, …) after System until he moves them among the branches, no recents or pins over them (Sven 2026-10-20), and typing there searches them all, hidden ones too, plus windows and files. Drawn as Line, Instrument's one layout since the feature trim (story 193; Classic and Rail went 2026-11-19). (not "launcher", "palette", "cheat sheet")
- **Launcher** — the app window's page for the menu, in an area of its own after Keys (P37, Sven 2026-10-18, Q284, Q285): Your menu (its root rows, Translate), Abilities (each with its own settings under it: repos, GIFs, passwords), Aliases and Quicklinks. The Menu page until the page map (Sven 2026-10-17, Q211), renamed Launcher on 2026-10-18; its links still say `page=menu`. The panel itself stays the menu. (not "Menu page")
- **Cursorline** — the current row of Line's root list (since Q139; the Classic layout's until the feature trim): a flat full-width band with a 3 pt accent bar in the gutter, as a terminal editor marks its line (story 193). (not "pill" or "highlight")
- **Line** — the menu's one layout since the feature trim (2026-11-19; the default from 2026-10-16): it opens as a narrow list, drawn as a terminal pane's (`ClassicMenu`, the Classic layout's look kept for Line's root), and the first key grows it into a 750 search whose line completes the best match and shows an answer's result; ⌘1–9 run rows, Cmd+K steps into the row, the kinds sit in the foot (story 193). (not "compact mode", Raycast's; not "Spotlight mode")
- **Search the web** — the row every root search offers under its best match (first when nothing matches), beside Ask AI: Return searches what was typed in the default browser with that browser's own default search engine; a Chromium browser's pick is read only with Full Disk Access, as Chrome guards it, else its built-in engine (story 193). (not "web fallback", not "Google it")
- **Morph** — Line growing from its narrow root list into its search on the first key, and back when the query empties: 200 ms out, 160 ms back, the search field never rebuilt (story 193). (not "transition", SwiftUI's word for one view's way in or out)
- **Answer card** — the first answer row of the menu (a sum, money, a time zone, a date, a colour, a translation) drawn big: what was typed on the left, the result on the right, a typed hex's swatch, ramp and five spellings; the row stays what Return copies, with Ask AI under it (story 74). (not "result card", "preview")
- **Line chip** — a picker at the right of the menu's search line that opens its list over the menu's top right: Emoji's category (⌘P), Translate's From, swap and To (Tab steps them, P40); the list takes the keys while open. (not "dropdown", "popover")
- **Clean** — the menu branch that shows Mole's preview of what it would remove and runs `mo clean` only after the confirm step, in the visible terminal (story 117). (not "optimize", "purge" — Mole's other commands, which Pilot does not run)
- **Report** — the record Pilot keeps of one Update or Clean run (story 153): when, the exact command, what it was asked to change, how it ended (done, failed with its exit code, cancelled) and what it printed; listed under Reports on Mac › Update & Clean, below Update and Clean, the newest 50 kept. (not "log", which is the system log; not "history")
- **Branch** — one level of the menu, e.g. Actions → Capture. Escape goes up one branch.
- **Frecency** — the ranking score: how often and how recently an entry was picked. Kept on the Mac.
- **Alias** — a short word on a Hyper+Space row (`wp`); typed exactly at the root search it lists that row first, a query only starting with it ranks as before. Kept by the row's frecency key in `aliases.json`.
- **File index** — Pilot's own index of the home folder that the menu's file search reads: a helper in the bundle built from Cardinal's MIT engine, kept current through FSEvents. Spotlight is not used. (not "Spotlight search")
- **Text index** — Pilot's own on-disk index (SQLite FTS5, `image-text.sqlite`) of the words Vision read in the images of the folders Text in images names, searched by the Files view for text hits (story 77). Read in a `pilot-text` child, never at search time, and kept apart from the file index. Switching Text in images off or Clear text index deletes it. (not "OCR cache", "Spotlight")
- **Downloaded from** — where a file came from, shown on its row as "from github.com": the site a browser saved it from (`kMDItemWhereFroms`), else the app that saved it (the quarantine's app name, "WhatsApp"); typed `from:<word>` filters on it (story 77). (not "origin", "source app")
- **Duplicates** — Files › Duplicates: groups of files with identical contents (SHA-256), found only when Scan is pressed, each keeping one copy while Move to Trash… sends the rest to the Trash after one ask (story 176). (not "look-alike photos", which are similar, not identical, and not in v1; not "clean up")
- **Folder design** — artwork Pilot sets as a folder's icon (Files › Folders, or Dress selected folders on Finder's selection in Hyper+Space): one of twelve designs Pilot draws, one of Your designs, or a picture of your own (story 196). (not "folder colour", "Customize Folder", which is macOS 26's own colour, symbol or emoji, never written by Pilot; not "theme")
- **Your designs** — pictures added to Pilot's own folder (Files › Folders › Add designs…) to dress folders in, kept as copies, each removable (story 196, P55). (not "Your own", the one picture picked each time; not "pack")
- **Dressed** — a folder wearing a folder design Pilot set and stamped; Reset takes back only a dressed folder's icon, putting back what it had before (story 196). (not "customised", which any custom icon is)
- **File actions** — the picker Hyper + right-click on a file opens at the pointer (story 199): Pilot's own actions for the files under it in Finder, on the desktop or in the menu's Files view, filtered by their kind (`FileAction`); a file row's Cmd+K in the menu stays its own list. (not "context menu", which is the app's own right-click menu, nor "Services", Finder's Convert/Resize with Pilot)
- **Desktop menu** — the native menu Hyper + right-click on the empty desktop opens at the pointer (Q743): Change wallpaper… (the wallpaper gallery), Wallpaper settings…, Add widget, New note, Show desktop, Look's style and theme and Desktop icons (Finder's own, off and on), each what the rest of Pilot runs (`DesktopMenu`); over a file it is File actions, over a widget the widget's own menu.
- **Show preview** — File actions' window showing one file's contents on Look's glass: Markdown rendered, text and code, a picture, a PDF's pages, else QuickLook's view; Escape closes it (story 199). (not "Quick Look", macOS's own panel, which File actions also offer)
- **Window search** — typing a window's title or app in the menu and jumping to it on any workspace.
- **Learn → Keybindings** — the menu branch listing every bind, the essentials first in Omarchy's order, searched, running one on Enter; what Hyper+K opens. Replaces the old "Hyper+K sheet". Distinct from the overlay.
- **Learn** — the menu branch that teaches keys: Keybindings only. Its config branches (This app, Shell, Ghostty, Git, Neovim, tmux, read live and read-only, story 78) have their parsers built and wait, parked, until after launch (Q132). (not "help", "cheat sheet")
- **Overlay** — the panel shown while Hyper is held 0.4 s: that sublayer's binds, all, most used or the user's pick. Up to five columns, then "+ N more"; its foot's Edit what shows opens Binds › Overlay.
- **Binds › Overlay** — the tab that picks what the overlay shows: every Hyper bind of the active preset with a Show switch. The pick is one set of actions for every preset; the first switch turns the overlay to My own pick.
- **Swap keys** — Binds › Swap keys: pairs of keys swapped at the HID level while Pilot runs, each typing the other (Caps Lock ↔ Left Control), written with Caps Lock's F18 as one UserKeyMapping set and taken off at quit (Q406). A Hyper key cannot be in one (Q407). (not "remap", which is another tool's mapping)
- **Pilot's tiler** — the tiling engine inside Pilot (`PilotTiler`), ported from AeroSpace (MIT); the only tiler since 2026-10-10 (ADR 0011). Changed 2026-10-10 (R3): AeroSpace, the separate app Pilot drove through its CLI, is gone; its `~/.aerospace.toml` is only read once, as an import.
- **Bar preset** — the top bar's shape, picked in Menu bar › Bar layout or with `pilot bar preset`: Full strip (id `fullStrip`: Attached, the whole width from the screen's top edge, the Full bar until 2026-11-15, saved as no preset; Floating, the floating strip, saved as `floatingStrip`), Three islands (an island per side) and Pills (a pill per item, each group one pill for all it holds). Each is Attached (hung from the screen's top edge) or Floating; each but Full strip Attached has its own default sizes, which Adjust sizes changes. (not "layout", "theme")
- **Group** — items sharing one slot in a bar, each keeping its own click: Group 1 is the Group (the readings start in it), and Group 2 and on are made by grouping an item into a new one (`pilot bar group <item> --group new`, or New group on the Menu bar page's strip), in the top bar alone, each its own pill on Pills (Sven, 2026-11-12, Q182). An extension's bar item can join one. (not "island", which is a side of Three islands)
- **Layout preset** — how a workspace's tiles are arranged: main + stack, centred main, rows, grid, scrolling or stage; one key, or a click on the shown workspace in the top bar, cycles all but rows; a workspace set to auto is laid out again when a window opens or closes. (not "layout mode", "tiling mode") Changed 2026-10-12 (ADR 0014): scrolling replaced accordion. Changed 2026-10-30 (ADR 0015): stage added. Changed 2026-11-14 (layouts round 1): main + stack is Sven's split (the right half 2x2 at five, then the newest tile halves), centred main added (its main in the middle half from the first window), columns gone (a stored one reads as scrolling), rows out of the cycle.
- **Layout glyph** — the shown workspace's layout drawn small in place of its number in the top bar (layouts round 1, Q234); a workspace with no layout keeps its number. (not "icon", a workspace's apps)
- **Scrolling layout** — a workspace root layout where each tiled window is a column on a strip that scrolls sideways (story 170, ADR 0014); replaced accordion on 2026-10-12. (not "accordion", "carousel", "niri mode")
- **Stage layout** — a workspace root layout that tiles the focused window's group in the centre (a joined group, or a window with its app's other lone windows) and shelves the rest in the hide corner, keeping 232 pt free at the monitor's left edge for the Window shelf (ADR 0015). (not "Stage Manager", macOS's own)
- **Window shelf** — the panel in that room on a Stage workspace: this workspace's shelved windows and groups and the windows minimized from it, the other workspaces folded below; a click focuses one, which brings its group to the stage, or restores a minimized one onto it (ADR 0015). "Shelf" in the UI. (not "Strip", a scrolling workspace's columns; not "sidebar", "rail", "tray")
- **Window pictures** — how the Window shelf draws a window: Stills (the default: a still taken as a window leaves the centre, refreshed every 2 s while the pointer is on the shelf), Live (a capture running per shelved window) or Off (its app's icon and title); pictures need Screen Recording, and until it is allowed the shelf shows icons and offers it once (ADR 0012, amended 2026-10-30 and 2026-10-31). (not "thumbnails", which are the capture's floating card; not "previews")
- **Column** — one place on a strip: a window, or windows joined into it as tiles, at its own width fraction of the usable width (1/3, 1/2, 2/3, full by default). (not "tile", "pane"; a tile is a slot in a tiles layout)
- **Strip** — the row of columns of one scrolling workspace, on the monitor that workspace sits on, two or three to a screen; it scrolls the minimum that brings the focused column into view, or centres it as the centre mode says (never, on overflow, always). Settings shows it as three pictures: Three on screen, One centred, Two on screen (layouts round 1). (not "canvas", "tape"; not the strip block an extension sends) Changed 2026-10-20: centre modes.
- **Column rule** — an app's own column on a strip: a width its windows' columns keep through every refit, and whether a window it opens takes focus (`pilot list column-rules`). (not "app rule", which sends an app's windows to a workspace)
- **Sliver** — the few pixels (5 by default) a column past an open screen edge keeps on screen; a click on it focuses that window. A column that would cross onto another display hides in the hide corner instead, never as a sliver. (not "peek", "edge")
- **Workspace preset** — a named setup for one workspace: its apps in order, laid out as a layout preset or at a size per app; switching to the workspace opens what is missing and pulls running windows in, never a duplicate. (not "profile", "scene")
- **Pilot block** — Pilot's tiling settings (app rules, always-float list, gaps, the top bar's room), kept in Pilot's own settings and handed to Pilot's tiler. Named for the marked block it once wrote into `~/.aerospace.toml`; changed 2026-10-10 (R3): that file is read once as an import, never written.
- **Always-float list** — the apps whose windows Pilot's tiler never tiles, kept in the Pilot block by bundle id (C8, 2026-10-10); a name from before that no app answers to is kept and matched by name.
- **Workspace** — a virtual workspace of Pilot's tiler, numbered from 1, nine by default and between 1 and 9 as the Workspaces page adds and removes them (story 62), each opening on its pinned monitor (story 148); windows on hidden workspaces are parked off-screen. Replaces "desktop" as the user-facing word. (not "desktop", "space" — a macOS Space is something else, and Pilot does not manage Spaces)
- **Tiled / floating** — a tiled window is placed by Pilot's tiler; a floating window is placed by Pilot (halves, thirds, ¾, centre) through Accessibility.
- **Pinned quick notes** — the notes panel pinned on screen (its head's pin, the Pin quick notes action, `notes.pinned`): it floats over other windows, stays open on a click outside or another app taking the keyboard, and keeps its moved and resized frame; Escape still hides it (Sven 2026-11-12). (not a pinned note, which ⌘P puts at the list's top)
- **Pinned window** — a window Pop out (Hyper+Alt+O) floated, centred and pinned: carried to the shown workspace of its monitor on every switch and raised, never parked; kept by Pilot's tiler only, so a restart drops it (story 180). (not "sticky", "always on top": it is raised, not kept above)
- **App rule** — an app pinned to a workspace (Ghostty → 1), kept in the Pilot block so the tiler places the window as it appears.
- **Rescue** — the action that pulls windows stranded off-screen on hidden workspaces back onto the main screen, run by its bind while no tiler runs and quietly at Pilot's launch (after a crash). Changed 2026-10-10 (R3): no prompt on AeroSpace's quit, no "always" tick.
- **Drive action** — an action that runs another app's command: its URL scheme, its menu item through Accessibility, a keystroke into the focused app, or the advanced field (URL, Shortcuts name, shell command). Never a keystroke aimed at another app's global hotkey (ADR 0001).
- **Menu item row** — a root search row for one menu item of the app Sven was in, read through Accessibility as the menu opens; Return presses it by its drive route, `drive.menu:<bundle id>:<path>` (story 132).
- **Drive catalogue** — the shipped JSON of known apps and their plain-English drive actions, each checked against the vendor's docs. An app with no route is "not supported". Each action is also its app's command in the menu (P38). (was "Catalogue")
- **App command** — one of an app's own commands the drive catalogue holds, listed at the menu's root search as a Command row under the app's icon ("Calendar · Command") and run by its route, never a key sent to the app (P38, Sven Q289). (not "app shortcut", parked; not "menu item row", read live from the app in front)
- **Setting row** — a root search row for a page or part of Pilot's window (`window.page:<name>`) or a System Settings pane (`system.pane:<id>`), found only by typing; the window's search lists the panes too (story 177).
- **Quicklink** — a named URL with a keyword, `{query}` in it filled with the words typed after the keyword in Hyper+Space (`gh pilot`); opens in the default browser, binds as `links.open:<id>`.
- **Script command** — an executable file in Pilot's Scripts folder, listed in Hyper+Space and bindable as `scripts.run:<file name>`; its Raycast-style header names its title, emoji icon and mode (silent, HUD line, visible terminal), and up to three arguments, typed after its title in Hyper+Space and passed as $1 $2 $3. It runs through the drive shell route.
- **Extension** — a folder in Pilot's Extensions folder (`~/Library/Application Support/Pilot/Extensions/`) holding `extension.json`: an id, a title, an icon, the permissions it declares (shown, not enforced) and its commands, each a program speaking JSON lines that Pilot runs and whose views Pilot draws (story 141, ADR 0010). Since ADR 0017 (proposed 2026-11-19) the format is Raycast's: a `package.json` manifest and its built JavaScript, run by the extension host, which replaces the JSON-lines programs extension by extension, never beside them. (not "plugin", "add-on")
- **Extensions folder** — `~/Library/Application Support/Pilot/Extensions/`, one folder per extension, read again each time the menu opens; Open Extensions folder shows it. (not "plugins folder"; the Scripts folder holds script commands)
- **Catalogue clone** — the person's clone of the catalogue's repo (banozz0/pilot, its `catalogue/` folder), set in `extensions.catalogueClone`, that `pilot ext publish` and `pilot theme publish` (the /publish skill, P49; public-repo T23) send an extension or a theme pack from as a pull request, from the person's fork (the clone's remote `pilot-fork`) when their GitHub account cannot push to the repo; every build sends from an account that can push, and sending from a fork stays in debug builds until it is proved against GitHub (SH19). (not "the catalogue", which is what Pilot installs from)
- **Extension command** — one command of an extension: a Hyper+Space row bindable as `ext.<id>.<command>`, no-view (a HUD line) or a view Pilot draws. (not "script command", which is a single file in the Scripts folder)
- **Extension session** — a list command marked `"session": true` whose one process stays running while its view is open, sent each search as a query message and stopped as the view closes (story 141, ADR 0010). (not "daemon" or "server"; a one-shot command runs again per search)
- **Extension preference** — a setting an extension declares (text, password, checkbox, dropdown, app, file or folder), its value kept by Pilot in the extension's ExtensionData folder or, for a password, the Keychain, and handed to every run in the run message (story 141, ADR 0010). (not "config" or "env var"; never passed in the environment)
- **Extensions page** — the app window's page: one list, the installed extensions then the extension catalogue's others (Q601), filtered All, Installed or Updates, the picked one's detail beside it: an installed one's settings, keys and what it touches, with the folders that failed and their reason (story 141); a catalogue one's Get, what you get and what it will touch (story 156, Q600). (not "extension store" or "plugin manager")
- **Extension detail** — a view Pilot draws for an extension in place of a list: markdown with facts beside it and actions under Cmd+K (story 141). (not "preview" or "page")
- **Extension host** — `pilot-ext-host`, the helper that runs one command of a Raycast-format extension on JavaScriptCore: a fresh context per run, its views sent to Pilot as list and detail lines that Pilot draws, gone once its view closes or its run settles; never resident (ADR 0017). (not "runtime", "Node"; not "extension session", which is how long one stays)
- **Prelude** — `pilot-ext-prelude.js`, the one JavaScript file the extension host loads before an extension: React, react-reconciler and Pilot's clean-room `@raycast/api`, built at dev time and committed, so building Pilot needs no Node (ADR 0017). - **Area** — the window's top level, above the pages, shown as a tab or in More: Home, Keys, Windows (Workspaces and Tiling), Launcher, Desktop, Look, Mac, Tools, Apps, AI, Extensions, Developer (Configs and Repos, only while the Developer pages switch is on) and Pilot (story 163; AI and Extensions since 2026-10-16, Launcher since 2026-10-18; Windows, Look and Developer since the pages split, 2026-11-15). A page shows only inside its area. (not "group", "section")
- **Page** — one screen of the app window: Home, Binds, Workspaces, Tiling and so on, listed down the left of its tab. (not "tab", which is an area in the tab bar; not "pane" — a System Settings pane is macOS's)
- **Style** — how Pilot draws as a whole: Instrument (graphite, one orange signal that means Hyper), dark or light as its theme is. It sits above the theme and every surface draws in it (story 137, ADR 0008); Current, the look before it, was removed 2026-10-11, and Toybox, the second style, in the feature trim (2026-11-19). (not "skin", "design", "theme")
- **Scale** — the one type step the app window, its pages and the Hyper+Space menu draw bigger than the rest of Pilot (PilotStyle.scale, 14/13: 13 pt text is 14), on every type role, the hand-set sizes of their views (Current's through Ink, Toybox's own faces through StyleTokens), the kit's rows, chips, buttons and fields, and the menu's panel; the top bar, panels and HUDs keep their sizes (story 163). (not "zoom", "text size")
- **Pilot page** (General until simplify-pages T4; `general` in links) — the app window's page for what is Pilot-wide: the Hyper key, Hold Hyper, health, startup and every permission Pilot asks for, Pilot's folder and the pilot command, and About (version, licence, credits, Send feedback). The Pilot page until C3 (story 163); Helpers went to Install and export and import to Binds in the page map (Sven 2026-10-17). (not "Settings", "Preferences")
- **Helper** — a command-line tool another feature runs, listed on Install › Helpers with what it unlocks and Install: Homebrew, Mole, mas, npm and cargo (PilotCore's `Helper`, `pilot list helpers`). Not the child programs in the bundle's `Contents/Helpers` (pilot-files, pilot-text, pilot-dictate), which ship with Pilot. (not "dependency", "plugin")
- **Theme** — a colour palette and its dark or light appearance, used by Pilot and participating apps. The ten designed palettes retain their names and saved selections; a theme pack can supply a custom palette. Style remains separate. (not "style", "skin")
- **Theme pack** — a saved, portable palette with compatible styles, optional wallpaper assets and supported app mappings. Saving or inspecting one changes no appearance. (not "personal config backup")
- **Destination binding** — the locally chosen app configuration destination a theme may change. Sharing a pack does not share permission to write to a destination. (not "pack authority")
- **Owned appearance** — the exact appearance file or region Pilot manages, with the original value and the last value it wrote. Switching packs retains the original; a later edit to that region conflicts instead of being overwritten.
- **Restore default appearance** — return owned appearance to its original value, or remove it if originally absent, preserving unrelated edits and saved packs. A conflict retains unresolved ownership for recovery. (not "factory reset")
- **Glass** — the Look page's one switch for the material behind the app window and every panel, popover and HUD: Liquid Glass when on, solid when off (Sven, 2026-10-09; Tinted and Panels always glass are gone). (not "material", "blur")
- **Transparency** — the Look page's slider for the app window, 0 % (solid) to 100 %, shown while Glass is on: each surface role (ground, sidebar, card, well, raised, free key) keeps its own strength over what it sits on, the signal and text stay whole, and the contrast floor lifts only the card. Instrument takes it. Replaced Strength (40 to 100 %, the other way round) in round 15, 2026-10-08. A Glass top bar's and dock's tint follows it too (Q714): solid at 0 %, 55 % at 33 %, 15 % at 100 % (42 % until 2026-11-14, lowered toward macOS's Liquid Glass). (not "strength", "opacity")
- **Blur** — the Look page's Glass blur under Transparency (2026-11-01): Full is Liquid Glass's regular style (the look until then), Light its clear style, Off no glass, the tint alone over a sharp desktop. It reaches the app window, the Glass panels, a top bar whose Background is Glass and the desk widgets; `look.glassBlur`. Look's Material sets it: Glass Full, Clear Light (2026-11-15); the bar's dropdowns and drops keep Full's regular glass at Light. macOS gives no blur radius, so these are its steps.
- **Restyled** — a surface a new style draws: listed in that style's `PilotStyle.restyled` once its designer's work lands. Surfaces: each page, the window's frame, the menu, the top bar, the overlay, the clipboard panel, the notes panel, the AI chat, the HUDs, onboarding.
- **System** — the app window's page (Setup until C3, story 163) that changes the Mac's sound, Bluetooth, Wi-Fi, displays and keep-awake inside Pilot, and says plainly what macOS refuses to an app instead of opening System Settings (story 113). Also the menu's System branch, which reaches the same controls. (not "System Settings pane", "control centre", "Setup")
- **Top bar** — Pilot's own bar along the top of each screen, drawn in place of the macOS menu bar, which it hides while it is on and gives back exactly when it is off (story 116). (not "menu bar", which stays macOS's; not "status bar", "Waybar")
- **Bar item** — one thing Pilot can show in the macOS menu bar, the top bar or both: 21 in six groups (Spaces and windows, Readings, Power, Sound and input, Time and focus, Layout), each with its styles and place in one order; one placed in both shows in the top bar while it is on and in the menu bar while it is off (card agent-bo-95422910). (not "module", the top bar's old word; not "widget") Extensions (story 161) is the bar item holding the extensions' bar items: each a short text with a tone, a dropdown of its blocks. The Menu bar page's Clear all, beside its Menu bar / Top bar / Both switch, takes every item off the bar picked there (off both for Both), the extensions' too, all but Pilot's own icon, which is pinned; Restore defaults beside it brings back the default items there; both are asked first, and `pilot bar clear` and `pilot bar restore` do the same, `--placement` naming the bar (Q411).
- **Capture item** — the bar item whose click lists every capture, the recording and the capture tools, each with its key; while a recording runs it shows the time and its menu leads with Stop and Pause. Tools › Captures › Capture menu places it (P69); a new install has it on in the macOS menu bar, never the top bar (Q368). (not "Capture branch", the Hyper+Space menu's level)
- **Bar drop** — a panel that drops from under the top bar on its key or its bar item: the terminal's (Hyper+T, real Ghostty) or Ask AI's (Hyper+Q); one open sits centred, both side by side, Terminal left; hidden, the terminal's shell keeps running (story 178). (not the Pilot menu, Pilot's bar item's panel; not "Strip", a scrolling workspace's columns; not "quick terminal", Ghostty's own)
- **Speech model** — a model Pilot's own dictation writes a take down with (Parakeet Ultra, Whisper large-v3 turbo or Whisper small, one in use), each downloaded from Voice › Dictation into its own folder in `Application Support/Pilot/Speech` and read by `pilot-dictate`, never in the bundle (story 194).
- **Mode light** — a glyph in the Mode lights bar item while one mode is on (keep awake, Night Shift, mic in use, clipboard paused, Secure Input, reminders queued); a click turns that mode off (story 181). (not "indicator", "status icon")
- **Bar tray** — under the Menu bar page's strip, every bar item not on the bar the page shows, by group: dragged onto the strip it lands where it drops, clicked it goes last; an item dragged off the strip onto it leaves that bar (Q185). Replaced the shelf, the parked on-bar edit mode's panel. (not "shelf", "palette")
- **Binds screen** — the app window's Binds page, listing every action with its bind in one list, a section per sublayer plus Other Hyper keys, Without Hyper (plain combos) and Not bound.
- **Move here** — the bind editor's Save when the picked action already holds another key: the action moves to the new key and its old key goes free, named before saving and logged (story 28). One action holds one key. (not "swap"; Replace is the Save that takes a key from another action)
- **Conflicts** — macOS system shortcuts that clash with a Pilot bind; all turned off so Pilot is the only app owning a global key, restored with one button. The macOS part goes through a private preference (`com.apple.symbolichotkeys`), not a public API.
- **Secure input** — the macOS state in password fields where the tap sees nothing; shown in the menu bar, never worked around.
- **Observers** — the engine's published state: focused app, focused window frame, window list, focused workspace per display. The game reads them later.
- **Milestone** — one step of the build order that ends with an app Sven can uninstall (A Karabiner-Elements, B Hammerspoon, C yabai and skhd, D Vicinae, E none, F ClipBook Rust), plus G, the designer pass that restyles every surface once the layout is built.
- **Tier** — when an action ships: v1, v1.1, v2, or no (macOS has no equivalent).
